How Lampas works

Lampas runs recursive agent work in four parts: a task arrives, an agent plans and decomposes it, child agents are spawned through the Fence where the work needs them, and results roll back up the tree. Governance is not a layer added afterwards — the Fence sits on the only path a spawn can take.

The ROMA pattern

Lampas follows the ROMA pattern (Recursive Open Meta-Agent): a meta-agent receives a goal, breaks it into sub-tasks, and dispatches each sub-task to an agent — which may itself act as a meta-agent for its own sub-tasks. Decomposition is recursive, so the shape of the work decides the shape of the tree, rather than a fixed pipeline decided in advance. Results are aggregated back up each level, so the originating run receives one coherent output from the whole tree.

The Fence check

Every spawn — every child or grandchild agent, at any depth — clears one check at the Fence before it exists. The Fence answers GRANTED or DENIED:

GRANTED

The spawn is registered as a child run of its parent, with its own depth and budget position in the tree, and begins work. The registration is what makes the run traceable.

DENIED

The spawn does not run. The requesting agent is told the spawn was denied and must finish with the agents it already has, split the work differently, or hand back. There is no retry path around the gate.

The same registration discipline applies on the Prometheon SI platform: creating a sub-chat in the unified app registers a child run with the Fence, carrying the parent run and conversation ids.

Depth & budget governance

Two limits travel with every run:

  • Depth — how many generations below the originating run a spawn may sit. The pilot's dedicated Fence bounded its generational demo at depth 3.
  • Budget — the spend and token envelope for the run and its descendants. Spawns that would exceed the remaining budget are denied.

Lifecycle rules apply as well: only records in an Approved state are eligible to serve, and disabled records are enforced at routing and at the Fence — a rule the pilot demonstrated live with a Candidate → Approved → Disabled pass.

Staging vs. production, plainly

The demonstrated result is a staging one: 17 agents to depth 3 under a dedicated Fence, with the Fence granting and bounding every spawn in the tree. Generational autonomy beyond those staging limits stays inside its existing governance, and this site does not present the staging result as production generational autonomy. Runs started from the console here are bounded Lampas runs through the live Prometheon SI gateway — the same backend, accounts, and Fence as prometheon.si.

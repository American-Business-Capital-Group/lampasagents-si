What Lampas is

Most agent systems only run the agents an operator scripted in advance. Lampas is built for generational work: a running agent can decide, on its own initiative, that a task needs help — and spawn a child agent to do it. That child can spawn its own children in turn. The generations form a tree of runs, each one registered, budgeted, and traceable back to the run that created it.

That freedom is bounded by design. Spawning is not a default; it is a permission, checked every single time by the Fence.

The Fence

Every spawn request clears one check at the Fence and comes back GRANTED or DENIED. A denied spawn does not run. Depth and budget limits are enforced at the same gate, so a runaway tree cannot form.

Generational spawning

Agents spawn on their own initiative when the work calls for it — not only where an orchestrator pre-scripted the tree. Each generation inherits its parent's task context under the same governance.

Depth & budget governance

Recursion depth and spend are capped per run. When a limit is reached, the Fence denies further spawns and the existing agents finish or hand back — the tree stops growing instead of failing open.

Pilot status, stated plainly

The pilot milestone ran 17 agents to depth 3 under a dedicated Fence: a parent run spawned children, children spawned grandchildren, and every spawn in the tree was a Fence decision. That is the demonstrated staging result.

Staging vs. production: generational autonomy beyond the staging limits demonstrated in the pilot stays inside its existing governance. Lampas does not promise production generational autonomy — the console on this site runs bounded Lampas runs through the same live gateway as Prometheon SI, under the same Fence rules.
